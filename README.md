# 논문 리뷰 집필 공간

## 독립 Windows 앱으로 사용하기

바탕 화면 **논문 블로그** 바로가기를 더블클릭하세요. VS Code나 Python 터미널을 열 필요가 없습니다.
`start-blog-app.cmd`와 `start-writing.cmd`도 같은 앱을 실행합니다.

왼쪽에서 글을 선택하고 가운데에서 편집하면 오른쪽에 실제 독자 화면이 표시됩니다.
입력 내용은 저장을 기다리지 않고 다음 화면 프레임에서 미리보기에 반영됩니다.
약 0.45초 쉬면 자동 저장하고, 약 2.2초 쉬면 현재 글만 발행용 렌더러로 검사합니다.
실시간 미리보기에서는 문장·표·코드·수식·흐름도를 확인할 수 있습니다.
인용 번호·상호 참조 등의 최종 표현은 독자 화면 오른쪽 **↻** 버튼으로 발행 화면을 확인하세요.
블로그 홈은 별도로 전체 목록을 갱신합니다.
상단 **저장**, **글 정보**, **저장하고 배포**와 이미지·수식·코드·흐름도 버튼을 사용할 수 있습니다.
**본문 / 읽기 메모 / 참고문헌** 탭을 전환해 논문 하나의 자료를 관리합니다.

**새 논문 리뷰**에서 제목과 영문 주소를 입력하면 기존 템플릿으로 글을 만듭니다.
참고문헌 탭에 BibTeX를 저장하면 `references.bib` 연결이 자동으로 추가됩니다.
본문의 `[@citation-key]`로 인용합니다.

처음 한 번 **GitHub 연결**에서 로그인합니다. 인증 코드가 앱 아래에 표시되면 브라우저에 입력하세요.
이후 **저장하고 배포**가 현재 글 공개 설정, 로컬 빌드, 커밋, 업로드, Pages 배포를 처리합니다.
초안 원문도 공개 저장소에 올라가며, 첫 배포는 기존 사이트 디자인을 교체합니다.
온라인 배포는 로그인과 실제 버튼 실행 후에 진행됩니다.

**작업 로그**, **작업 중지**, **배포 상태**에서 진행 상황을 확인할 수 있습니다.
다른 프로그램에서 같은 글을 변경하면 저장 충돌을 표시하며 덮어쓰지 않습니다.

최신 빌드의 실행 파일은 `.tools/apps/fast-preview/PaperBlog/PaperBlog.exe`입니다. 옆의 `_internal` 폴더는 앱 실행에 필요합니다.
실행 검증을 마친 빌드만 기존 앱을 대체합니다. Windows 앱 제어가 새 빌드를 차단하면 기존 바로가기를 유지합니다.
기존 앱의 웹 화면만 갱신할 때는 `tools/update-blog-ui.ps1`을 사용합니다.
실행 파일은 변경하지 않으며, 이전 웹 화면을 `.tools/ui-backup-*`에 보관합니다.
이전 실행 파일에서도 입력 즉시 갱신과 자동 저장을 사용할 수 있습니다. 정확한 발행 렌더링은 **↻** 버튼으로 실행합니다.
앱 소스는 `tools/blog-app/`, 빌드 스크립트는 `tools/build-blog-app.ps1`입니다.
이 PC의 WebView2를 사용하며, Python 런타임은 앱에 포함됩니다.

아래 VS Code 패널은 기존 사용 방식으로 남겨 두었습니다.

## 블로그 디자인

앱을 다시 연 뒤 독자 화면 상단 **블로그 홈**을 누르면 전체 디자인을 볼 수 있습니다.
CSS Design Awards 선정작의 타이포그래피, 컬렉션 탐색과 시각적 아카이브를 참고했습니다.
큰 PAPER NOTES 타이틀, 자체 SVG 입체 그래픽, 비대칭 리뷰 목록, 검색과 가벼운 움직임을 적용했습니다.
본문에는 고정 목차, 논문 정보 표, 수식·코드·그림 캡션과 읽기 진행 표시를 제공합니다.

새 글은 기본 커버가 자동 적용됩니다. 개별 커버는 글 위쪽 `image: figures/cover.png`로 지정하세요.
`paper-title`, `paper-venue`를 추가하면 목록에 원 논문 제목과 학회 정보를 표시합니다.
디자인 참고 링크는 `styles/design-reference.md`에 기록했습니다.
로컬 디자인 변경은 앱의 **저장하고 배포**를 실행했을 때 온라인에 반영됩니다.

## 버튼으로 사용하기

VS Code 왼쪽 활동 표시줄의 책 아이콘 **논문 블로그**를 누르면 집필 버튼 패널이 열립니다.
아래 상태 표시줄의 **블로그 집필**도 같은 패널을 엽니다.
`.qmd` 탭 오른쪽 위에도 저장·미리보기·배포 버튼이 있습니다.

| 버튼 | 하는 일 |
|---|---|
| 모두 저장 | 집필 폴더의 편집 중인 글과 메모 저장 |
| 독자 화면 미리보기 | 현재 글 저장·렌더링 후 오른쪽에 실제 화면 표시 |
| 데스크톱 / 모바일 | 독자 화면 패널에서 너비 전환 |
| 새 리뷰 | 제목·영문 주소 입력 → 템플릿 생성 → 글과 미리보기 열기 |
| 읽기 메모 | 현재 논문의 비공개 로컬 메모 열기 |
| 글 정보 | 제목·설명·카테고리를 입력창으로 변경 |
| 이미지 삽입 | 이미지 선택 → figures에 복사 → 본문에 삽입 |
| 수식 / 코드 / 흐름도 삽입 | 커서 위치에 작성 틀 삽입 |
| 초안으로 변경 | 글을 초안으로 전환; 온라인에서는 다음 배포 때 반영 |
| 저장하고 배포 | 저장 → 현재 글 공개 설정 → 빌드 → 커밋 → push → Pages 배포 → 완료 확인 |
| GitHub 연결 | 처음 한 번 브라우저 OAuth 로그인 |
| 배포 상태 / 사이트 열기 / 작업 로그 | 결과와 오류 확인 |

**첫 연결:** GitHub 연결 버튼을 누르고 터미널의 안내에 따라 로그인합니다.
브라우저 인증 후 배포 버튼을 누르면 됩니다. 비밀번호나 토큰을 이 프로젝트에 입력할 필요는 없습니다.
처음 배포하면 기존 Jekyll 사이트 대신 새 Quarto 사이트가 공개됩니다.
기존 파일과 Git 이력은 보존되지만, 기존 글은 Quarto 목록으로 자동 이관되지 않습니다.

현재 글만 `draft: false`로 전환합니다. 다른 초안의 상태는 유지됩니다.
사이트 설정, 코드, 글 원문은 공개 GitHub 저장소로 올라갑니다. 비공개 메모와 PDF는 제외합니다.
빌드 실패 시 수정하지 않은 글의 초안 상태를 복구하며, 원격에 더 새로운 변경이 있으면 덮어쓰지 않습니다.
빌드 도중 편집하면 배포를 중단하므로 다시 저장한 뒤 배포하세요.

배포에는 이 저장소의 쓰기 및 Pages 관리 권한이 있는 GitHub 계정이 필요합니다.
처음에는 현재 로컬 브랜치를 원격 기본 브랜치로 fast-forward 업로드합니다.
브랜치 보호 규칙이나 수동 승인 환경이 있으면 버튼과 로그에 GitHub의 거부 이유가 표시됩니다.

패널 설치·갱신은 `start-writing.cmd` 실행 시 자동으로 처리합니다.
확장 소스는 `tools/writing-panel/extension/`에 있고, 로컬 VSIX 패키지는 `.tools/`에 생성됩니다.

## 바로 시작하기

`start-writing.cmd`를 더블클릭하면 집필 패널을 설치하고 VS Code를 엽니다.
처음 열 때 작업 공간 신뢰 안내가 나타나면 이 로컬 프로젝트의 내용을 확인하고 진행하세요.
집필 패널에서 **독자 화면 미리보기**를 누르면 오른쪽에 독자 화면이 열립니다.
패널이 보이지 않으면 VS Code의 **창 다시 로드**를 한 번 실행하세요.

미리보기 주소: <http://127.0.0.1:4200>

첫 리뷰 파일은 `posts/first-review/index.qmd`에 준비되어 있습니다.
읽기 메모는 `notes/first-review.md`에 작성합니다.

`posts/writing-sandbox/index.qmd`를 편집해 보세요. 1.5초 뒤 자동 저장되며 화면이 갱신됩니다.
수동 저장은 `Ctrl+S`입니다. 렌더링 시간만큼 수 초의 지연이 있을 수 있습니다.

## 편집기 옆에 화면 띄우기

- `.qmd` 파일을 열고 오른쪽 위 **Preview** 버튼을 누릅니다.
- 또는 `Ctrl+Shift+P` → **Quarto: Preview**를 실행합니다.
- Quarto 확장은 설치되어 있고 미리보기 위치는 `internal`로 설정되어 있습니다.
- 미리보기에 쓰일 profile을 묻는다면 **preview**를 선택합니다.
- 외부 브라우저가 편하면 `Ctrl+Shift+P` → **Tasks: Run Task** → **블로그: 미리보기 시작**을 실행합니다.
- 전체 사이트의 초안 목록은 미리보기 주소에서 볼 수 있습니다.
- 모바일 표시는 브라우저에서 `F12` → `Ctrl+Shift+M` → 기기/화면 폭 선택으로 확인합니다.

하나의 미리보기 서버만 사용하세요. VS Code Preview가 포트 충돌을 알리면 기존 명령 창에서
`Ctrl+C`로 서버를 종료한 뒤 Preview를 다시 실행합니다.

## 새 논문 리뷰 만들기

`Ctrl+Shift+P` → **Tasks: Run Task** → **블로그: 새 논문 리뷰**.
영문 폴더명과 한글 제목을 입력하면 다음 파일을 생성하고 엽니다.

```text
posts/paper-slug/index.qmd       게시할 글
posts/paper-slug/references.bib  BibTeX 인용 정보
posts/paper-slug/figures/        글에 넣을 그림
posts/paper-slug/code/           예제 코드
notes/paper-slug.md             로컬 읽기 메모
```

메모는 편집 자유도가 높은 Markdown으로, 글은 수식·인용을 지원하는 Quarto Markdown으로 씁니다.
논문 PDF는 루트의 `papers/` 폴더를 만들어 보관하면 Git에서 제외됩니다.

## 자주 쓰는 문법

```markdown
인라인 수식: $X \in \mathbb{R}^{B \times N \times D}$

$$
Y = XW
$$ {#eq-projection}

@eq-projection 에서 입력 특징을 투영한다.

![모델 구조](figures/architecture.png){#fig-architecture}

@fig-architecture 를 따라 데이터 흐름을 설명한다.
```

일반 `python` 코드 블록은 실행하지 않고 표시합니다. 집필 중 자동으로 코드를 실행하지 않도록
설정되어 있습니다. 실행 결과는 별도 실험에서 검증한 뒤 그림·표로 가져오세요.

인용할 논문의 BibTeX를 `references.bib`에 넣고 글 위쪽 YAML에
`bibliography: references.bib`를 추가하면 `[@citation-key]`로 인용할 수 있습니다.

## 초안과 발행 화면

새 글은 `draft: true`로 생성됩니다. 로컬 미리보기에는 보이지만 발행 빌드에는 본문이 포함되지 않습니다.
발행할 글만 `draft: false`로 바꿉니다. 이 표시는 웹사이트에 대한 것으로,
GitHub에 push한 글의 원문 자체는 공개 저장소에서 읽을 수 있습니다.
비공개 읽기 메모는 Git에서 제외하는 `notes/`에 보관하세요.

`Ctrl+Shift+B`는 실제 발행용 `_publish/` 폴더를 만듭니다. 미리보기는 별도의 `_preview/`를
사용하므로 발행 빌드가 집필 화면과 섞이지 않습니다.

## 현재 Git 상태와 배포

기존 Jekyll 파일과 글은 보존되어 있습니다. 이번 환경은 로컬 `writing-preview` 브랜치에 준비되어 있으며,
온라인 사이트에는 아직 반영하지 않았습니다. 이전 글은 새 Quarto 목록에 자동으로 이관되지 않습니다.

GitHub Actions 워크플로는 **main에 push하면 자동 실행**됩니다. 필요하면 수동으로도 실행할 수 있습니다. Pages는 GitHub Actions 배포 방식으로 전환되어 있습니다. 다른 저장소에서 처음 설정할 때는:

1. 디자인과 집필 흐름을 확인합니다.
2. 기존 글의 이관 여부와 URL 유지 방법을 결정합니다.
3. 변경 사항을 GitHub의 기본 브랜치에 반영합니다.
4. Settings → Pages → Source를 **GitHub Actions**로 변경합니다.
5. Actions → **Publish Quarto blog** → **Run workflow**로 배포합니다.

자동 push 배포가 필요하면 이후 워크플로에 `push` 트리거를 추가할 수 있습니다.

## 다른 PC에서 실행

Windows에서 패널의 기능을 처음 실행하면 프로젝트 내부 `.tools/`에 고정 버전 Quarto와 GitHub CLI를
다운로드하고 SHA256을 확인합니다. 시스템 PATH를 변경하지 않습니다.
VS Code의 Quarto 확장을 설치하고 `.vscode/settings.json`의 `quarto.path`를 새 경로에 맞추세요.
